Backup, restore and migration

A league is a folder. Backing it up is copying the folder at a moment when no host writes to it; restoring it is putting the copy back and checking it.

What to back up

ItemBack upWhy
league/AlwaysThe registry and every game's ledger: the league itself
events.jsonlAlwaysThe host's record of starts, commits and stops; part of the audit evidence
loopback/leasesAlwaysWhich laptop held which address in this league; it keeps every laptop unique in the league after a restore ({{ref:lease-file}})
The laptop's device fileOptionalKept outside the data folder; derived again from the machine when lost, so the laptop keeps its key ({{ref:device-file}})
browser_profile/Never neededThe window's browser profile; a new one is made when absent
.rinkvt.lockNeverA lock belongs to a running host
The release folderOptionalCan be obtained again from its source and verified; keeping a copy of the exact release that wrote a league is good practice for an audit

Backup procedure

  1. Stop the host: stop host in the window, or Ctrl+C in its console. Every recorded line is already on disk.

  2. Copy the data folder, without browser_profile/ and .rinkvt.lock, to the backup location, preferably under a name that carries the date: rinkvt-league-2026-11-15.

  3. Verify the copy: RINKVT.cmd --verify-only --data rinkvt-league-2026-11-15 (./rinkvt.sh on macOS and Linux). The league part of the report must say "ok": true.

  4. Keep the copy on a different disk from the original (DAT-01).

A copy taken while a host runs is not a backup to rely on: files are copied at different instants, and a copy may hold a cut-off last line or a pending registry seal. Stop the host first.

Restore procedure

  1. Stop any host that uses the data folder.

  2. Move the current data folder aside under another name. Do not delete it until the restored league has been checked.

  3. Copy the backup into the data folder's place.

  4. Verify it with --verify-only.

  5. Start the host. The window shows the league as it was when the backup was taken.

Checking a league without a host

--verify-only reads a data folder and writes nothing to it: no lock is taken over, no cut-off line is dropped, no pending seal is completed. It is therefore safe on a backup, on a copy received from another operator, and on removable media. When a running host holds the folder, it checks the release only and says that the league is to be verified from that host's window with store verify.

Moving to another computer

  1. Back up the data folder on the old computer ({{ref:backup-procedure}}).

  2. Install and verify the same release, or a later one, on the new computer.

  3. Restore the backup into the new computer's data folder and start the host.

The new laptop has an identity of its own and therefore an address of its own: lines typed on it record its address, and the from column of earlier lines keeps the old laptop's. An address belongs to one laptop for good, so a replacement laptop never takes over its predecessor's; the restored lease table keeps both, unique. A reinstall of RINK-VT keeps the laptop's identity; a reinstall of Windows or Linux gives the machine a new identifier, and the laptop is then a new device ({{ref:device-identity}}).

Updating the release

A later release of the LK/Vexa edition opens a league written by an earlier one when it keeps the registry schema rinkvt.registry.v1 and the ledger format rinkvt.vec1-ledger.v1; its notes say so when it does not. To update: stop the host, back up the data folder, replace the release folder with the new release (keeping the data folder), verify the new release, and start it.

Between the editions

The editions share the registry schema and the frame and meta-line formats, but not the ledger file format: the reference edition keeps SSD-RAM files of 64-byte records ({{ref:reference-ledger}}), this edition hash-chained JSON lines. A data folder of one is therefore not opened by the other. The lines of a game can be carried across by replaying its entries, and the registry text is the same document; no tool for this is supplied in this release.
