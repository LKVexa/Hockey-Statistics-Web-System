What the tests establish

Leases
Canonical keys in every spelling; pools refused when invalid; the same addresses and the same probing as the reference edition; leases static across restarts and unique over thousands of addresses; a full pool refused; one table shared by two writers; a cut-off line dropped; an edited line and a changed pool refused.
Store
Commits that survive reopening; entries written by the engine itself accepted; stale seals, wrong starts, removed games, bad seals, half pairs, bad base64 and unknown games refused with nothing written; invalid registries refused; cut-off lines dropped on opening and reported by verification without repair; edited entries, removed lines and an edited registry refused; an interrupted registry commit completed, and a commit cut off before its rename discarded.
Host API
The page carries its token and every security header; the Host guard refuses every other name; the token guard refuses missing, wrong and altered tokens; mutations refused for the wrong media type, a foreign origin, a missing token, duplicate keys, a non-object and an oversized body; only the bundle and stylesheet served as files; a full commit, league, ledgers and verification round trip, with stale seals refused.
Release
A sealed release passes; a changed, missing or unlisted code file is refused and the host exits 4; a documentation change does not stop a start but fails a full verification; the bundle is current; the page obeys its own policy.
Contracts
Every static record valid and equal to what the generator writes, and accepted by the corpus validator when it is present; the validator refuses damaged documents; the JA sources well formed; their constants equal to the implementation's; the JA checker refuses what the suite refuses.
Browser
The real host in its own process and the workbench in Chromium: a game created and scored, each line recorded, the audit trail naming this computer's lease, the league intact across a reload and across a restart of the host with the same lease, store verify OK; a simulation recorded; two windows racing, the later refused and reloaded; no page or console error.

Running the tests

python -I -B -m unittest discover -s tests -p "test_*.py"                 the whole suite
python -I -B -m unittest discover -s tests -p "test_store.py" -v         one module, naming each test
RINKVT_MSSL_VERIFIER=…/VERIFY_MSSL.py python -I -B -m unittest discover -s tests -p "test_*.py"
RINKVT_SKIP_BROWSER=1 python -I -B -m unittest discover -s tests -p "test_*.py"   without the browser tests

The browser tests copy the release to a scratch folder, seal the copy and start its host in a process of its own, so they test the host exactly as a start runs it and leave the working tree untouched.
