Store
Commits that survive reopening; entries written by the engine itself accepted; stale seals, wrong starts, removed games, bad seals, half pairs, bad base64 and unknown games refused with nothing written; invalid registries refused; cut-off lines dropped on opening and reported by verification without repair; edited entries, removed lines and an edited registry refused; an interrupted registry commit completed, and a commit cut off before its rename discarded.
Host API
The page carries its token and every security header; the Host guard refuses every other name; the token guard refuses missing, wrong and altered tokens; mutations refused for the wrong media type, a foreign origin, a missing token, duplicate keys, a non-object and an oversized body; only the bundle and stylesheet served as files; a full commit, league, ledgers and verification round trip, with stale seals refused.

Contracts
Every static record valid and equal to what the generator writes; a well-formed document accepted, and a changed fact, rule count, rule number, rule form, envelope or projection refused; the JA sources well formed; their constants equal to the implementation's; the JA checker refuses what the suite refuses.
Earlier releases
A league, an event ledger, a device file and a lease table written by the earlier host, with names outside ASCII among them, open and verify; the device file keeps its address and fleet register, the lease table its leases; and the league still verifies after this host has committed to it and recorded an event.
This guide
The PDF reader and writer; the numbering of headings, tables and figures and their cross-references; the test inventory; and the whole guide printed by a browser, with its destinations, page labels, bookmarks, document information and a running header and footer on every page but the cover.

The real host in its own process and the workbench in a Chromium-family browser, driven over its DevTools protocol: a new game's clock standing still until its start frame, GO refused before START, a second START refused, the start frame in the audit trail; the whistle by Esc (the half-typed line kept), by its chip and by WHISTLE mm:ss, refused before the start and on a stopped clock, in the audit trail and replayed after a reload; a league's overtime rules set by preset, a tie that stands with its point and its standings column, an international playoff game with a 10:00 3-on-3 overtime and a five-round shootout, and a game keeping the rules it was created under; a game created and scored, each line recorded, the audit trail naming this computer's lease, the league intact across a reload and across a restart of the host with the same lease, store verify OK; a simulation recorded; two windows racing, the later refused and reloaded; no page or console error.

Running the tests

The tests are Go tests and run with the Go toolchain, 1.22 or newer, in photon/; nothing else is needed. They are a maintainer's tool: a computer that only runs or verifies the workbench needs neither them nor Go.

go test ./...                                         the whole suite
go test -count=1 -v -run 'TestStore' ./...            one group, naming each test
RINKVT_SKIP_BROWSER=1 go test ./...                   without the browser tests
RINKVT_TEST_BROWSER=/path/to/chrome go test ./...     with a browser the tests do not find themselves

The browser tests copy the release to a scratch folder, seal the copy and start its host in a process of its own — the test program itself, started again as the host — so they test the host exactly as a start runs it and leave the working tree untouched. contracts qualify runs the whole suite once more, from a clean cache, and writes the qualification record from what the run showed.
