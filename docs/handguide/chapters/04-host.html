Operating the Photon host

The Photon host is the program an operator starts. It is a single Python process, standard library only, that checks the release, keeps the data folder, serves the workbench on a loopback address and opens the window.

The command line

The launchers START_RINKVT.cmd and START_RINKVT.sh find Python 3.10 or newer and run photon/rinkvt.py with the interpreter's isolated mode (-I: no user site packages, no environment-provided paths) and without bytecode files (-B), passing their own arguments on. The host takes the following options.

The environment variable RINKVT_BROWSER, when set to the path of a Chromium-family executable, is tried before the browsers the host looks for itself ({{ref:renderer}}).

The start sequence

A start runs the following steps in order. A step that fails ends the start with the exit code shown, before anything is listened on; nothing in the data folder is changed by a refused start except as stated.

  1. Check the release. Every file under photon/, ui/ and engine/ must be listed in RELEASE_MANIFEST.json with its SHA-256, and every listed one present and unchanged. Otherwise the start is refused with the lists of missing, changed and unlisted files (exit 4). Documentation, tests and contracts are sealed too, but only a verification checks them ({{ref:manifest}}).

  2. Take the data folder. The folder is created if absent, and the host creates .rinkvt.lock in it exclusively, holding its process id, its computer's name and the time. If the file exists and names a live process on this computer, the start is refused (exit 5); if it names another computer, the start is refused too, because a data folder belongs to one computer at a time; if it names a process that is gone, the lock is stale and is taken over.

  3. Open the league. The registry is read and its seal checked; every game's ledger is read and its chain and seals checked. A last line cut off by a stop during a write is dropped (it was never acknowledged) and the window is told which games had one. Any other damage refuses the start (exit 6) and names the file and line ({{ref:recovery}}).

  4. Lease the loopback address. The IP address is --address, or this computer's primary address: the source address of its default route (found without sending a packet), else the address of its host name, else 127.0.0.1. The lease table gives that address its static loopback address, making the lease on first contact ({{ref:loopback}}). A damaged, full or locked table refuses the start (exit 7).

  5. Listen. A fresh 256-bit token is drawn for this launch. The host listens on the lease address, or on 127.0.0.1 when the system has no such address (macOS without an alias), on the first free port of 8800–8829, else one the system assigns (exit 7 when none). The start is recorded in the event ledger.

  6. Serve. The host prints its report and, after 0.3 s, opens the window. It serves until it is stopped.

The report names everything a start decided:

RINK-VT {{version}} · LK/Vexa edition (Photon-hosted)
  loopback 127.20.66.113 · static for 203.0.113.5
  workbench  http://127.20.66.113:8800/
  league     C:\RINK-VT\runtime (12 games)
  The listener is loopback only; Host, Origin and a per-launch token guard it. Ctrl+C stops the host.

Files of the league are created with permission mode 0600 where the system honours it. Writes go through the operating system's synchronous write path: a ledger line, a registry and an event are each written whole and synced (fsync) before they are acknowledged.

The renderer window

The host opens the workbench in the first of these browsers it finds, after RINKVT_BROWSER if that is set:

SystemCandidates, in order
WindowsMicrosoft\Edge\Application\msedge.exe, then Google\Chrome\Application\chrome.exe, then Chromium\Application\chrome.exe, each under Program Files (x86), Program Files and the user's local application data
macOS/Applications/Microsoft Edge.app, /Applications/Google Chrome.app, /Applications/Chromium.app
Linuxmicrosoft-edge, microsoft-edge-stable, google-chrome, google-chrome-stable, chromium, chromium-browser on the path

The browser is started in app mode on the workbench's address, with --user-data-dir set to browser_profile/ in the data folder, extensions disabled, and no first-run or default-browser prompts. The window is therefore isolated from the operator's ordinary browsing: no extension can read the page and no cookie or session crosses either way. Without a candidate, the host prints the address to open; with --allow-default-browser-fallback it opens the address in the ordinary browser instead, with that browser's extensions and profile.

Ports and addresses

The listener is bound to the lease address and nothing else; it is never bound to a network interface or to all addresses. The port is the first free one of 8800 to 8829, so that a bookmark usually keeps working, or --port. Several hosts on one computer, each with its own data folder, therefore take consecutive ports. The address in the window's location is the lease address and port; the host answers no other Host header ({{ref:guards}}).

Stopping and signals

The host stops on Ctrl+C; on stop host in the window, which first commits anything outstanding and then calls POST /api/shutdown; on SIGTERM or SIGHUP (POSIX); and on SIGBREAK (Windows). On a stop it closes the listener, records stop in the event ledger and releases the data folder. If the system ends the process before that — a forced kill, a power cut — nothing acknowledged is lost, and the next start finds the lock stale and takes it over.

Operating obligations

OPS-01The operator MUST keep the host's console open while the workbench is in use; closing it stops the host.
OPS-02The operator MUST NOT edit, rename or delete files in the data folder while a host has it open, and SHOULD NOT edit them at any time; the host refuses an edited file rather than guess.
OPS-03The data folder SHOULD be on a local disk and SHOULD be excluded from file-synchronisation services while a host has it open; such services can hold files open across the renames a registry commit makes.
OPS-04The operator MUST NOT run hosts on two copies of one data folder and expect to merge them: there is no merge, and the copies diverge.
OPS-05The operator SHOULD run VERIFY_RINKVT after installing, copying or updating a release ({{ref:verify}}).
OPS-06The operator SHOULD use the window the host opens; a window opened on another host's address is a window of that host.
