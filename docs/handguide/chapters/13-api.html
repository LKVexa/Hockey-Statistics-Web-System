The host API

The host speaks HTTP/1.1 on its loopback address. Its API has ten routes; every one is guarded, and every answer carries the same restrictive headers.

A HEAD request is answered like a GET without a body. The ledger route takes the seal so that the registry and the ledgers the window loads belong together: if a commit lands between the two requests, the window asks again.

Admission of a request

Every request passes these guards in this order, and the first that fails answers. A GET or HEAD passes guards 1 and 4; a POST passes all six.

#GuardRuleRefusal
1HostThe Host header names the address and port the host listens on (and, when that is 127.0.0.1, also localhost and the port), compared exactly after lower-casing. This defeats DNS rebinding: a page of another site cannot make the browser send this host's name421 misdirected request
2OriginA POST that carries an Origin header names this host's own origin403 cross-origin
3Media typeA POST is application/json, which a plain HTML form cannot send415
4TokenEvery /api route but /api/health carries X-VEC1-Token equal to this launch's 256-bit token, compared in constant time. The token is in the page the host served, which no other origin can read403 forbidden
5BodyA declared Content-Length of at most 32 MiB; no chunked bodies; the body read in full411, 413, 400
6JSONStrict JSON: no duplicate keys, no NaN or Infinity, nesting at most 64 deep; the body is an object400

Requests are not logged. An unexpected exception answers 500 with the exception's type only, and records an internal_error event naming the route and the type, never the request's content.

The commit request

POST /api/commit HTTP/1.1
Host: 127.20.66.113:8800
Content-Type: application/json
X-VEC1-Token: …

{"base": "540f79c5…" | null,
 "registry": "{\n \"schema\": \"rinkvt.registry.v1\", …}\n",          optional: the whole new registry text
 "ledgers": [{"game": "G1", "uuid": "3913755b-7df0-56f3-a423-d01281f42143",
              "start": 2, "data": "AZPv…"}]}                          base64 of whole 128-byte pairs

base is the registry seal the window last saw, null before the first registry exists. The answer, after the commit is synced, is {"registrySha": "…", "counts": {"G1": 3}}. A commit that carries neither a registry nor entries is answered without writing anything.

The page

The page is ui/workbench.html with three placeholders replaced when it is served: the launch's token, this computer's lease and the IP address it is static for, each in a <meta> element the page reads at start (rinkvt-token, rinkvt-local, rinkvt-client). The page loads only /workbench.css and /workbench.js from the host, and has no inline script, style or event handler, as its policy requires.
