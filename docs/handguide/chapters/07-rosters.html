Rosters and references

A scorer types four-letter references: a team, a player. A league's clubs and rosters usually exist already in a spreadsheet or an export, and the importer turns such a file into registered leagues, teams and players, each with its reference.

Four-letter references

Every league has a LEAGUE_4, every team a TEAM_4, every player on a team a PLAYER_4. League and team codes are one namespace, and the reserved words of the language are never codes, so a code means one thing wherever it is typed. A reference that exists is never changed.

League and team codes

A code a file gives is used as it stands. Otherwise LEAGUE_4 comes from the league's name and TEAM_4 from the team's city (the specification's "municipal identity"), or, without a city, from its name less its last word, the nickname.

Small words (of, the, de, du, des, la, le, les, and, et, at, au, aux) do not count; accents, apostrophes and periods are dropped; a hyphen separates words. A name too short borrows from the nickname, then X fills. When the first choice is taken, the next are, in order: the other splits (3 + 1, 1 + 3; 1 + 2 + 1, 1 + 1 + 2); the first three letters with each later letter of the name (KELO taken → KELW); with A to Z; the first two with AA to ZZ; the first with AAA to ZZZ.

Player codes

PLAYER_4 is the first four letters of the surname (SMIT). A short surname takes letters of the given name (Roy, Philippe → ROYP). When a team-mate already has the code, the rule takes three letters and the given-name initial (SMIR), then three letters and the last digit of the jersey (SMI9), then two letters and two digits, then letters. J91 and 0091 remain aliases of jersey 91. Codes a file gives are set aside before any is designated, and the rule is deterministic, so one file gives the same references whatever the order of its rows.

Columns may be in any order, in English or French, with headers as people write them (Jersey #, N°, Shoots (L/R), Date of birth, Prénom). The league columns are league, league_code and league_abbr; the team columns team, team_code, city, arena and timezone; the player columns player or name ("Smith, John" or "John Smith") or last_name with first_name, jersey, pos (C LW RW D G; a forward of no stated line is recorded as C), shoots (L R), born, import and player_code. A date such as 03/04/2006, which could be March or April, is left out rather than guessed. A cell left empty under a team or league means the same as the row above.

Importing in the workbench

  1. Choose the file with the chip your roster file…, or write the examples into the window's file system with rink import examples and name one, such as rink import rosters/roster.md. The window cannot read paths of the computer's disk; the file chooser is the way a file of this computer reaches the engine ({{ref:picker}}).

  2. Read the preview. It is the registration itself, run on the registry and undone, so what it shows is what --apply does: the leagues, teams and players, which are new, the reference each would receive, and every error and warning with its place (line 12, sheet "Teams" row 4).

  3. Register it with rink import NAME --apply. The registry is written once: all of the file, or nothing when any record is in error (--skip-errors registers the rest). The change is recorded by the host like any other ({{ref:recording}}).

  4. List the references with rink refs (every league and team) and rink refs TEAM (a team's players as they are typed).

Further options: --show=TEAM (or --show=all) lists players; --league="Name" places teams that name no league; --assign-jerseys gives players without a number a free one, from 99 down; --page=N shows the next hundred. rink import formats prints the columns and layouts the importer reads.

Importing again

What is registered is recognised, not doubled: by its code when the file gives one; otherwise a league by its name or abbreviation, a team by its name (in its league first), a player by surname and given name on the team, with the jersey or birth date telling namesakes apart. A later file updates a league's or team's French name, arena, city, time zone and league, and a player's jersey, position, hand, import flag and a birth date that was unknown. Codes, a player's name and a known birth date do not change. An import adds and updates; it removes no one, and there are no transfers in this version: a player registered with another team under the same name and birth date is refused.

What is refused

  • A player with no jersey number (unless --assign-jerseys), a number outside 1 to 99, a number a team-mate keeps, a player with one name only.
  • A code that is taken or is a word of the language; a name that fits two teams, until the file gives the code.
  • A file that is not what its extension says, is password-protected, or exceeds the limits: 4 MiB and 60 000 rows a file; 48 MiB inflated and 64 sheets a workbook; 64 leagues, 1 000 teams and 80 players a team in the registry.

A file is data, never a program. Nothing in it is evaluated — no formula, no macro, no XML entity beyond the five built-in ones, no external reference — and every reader stops at its limits. A workbook that would inflate beyond its bound is refused, not expanded.

Adding by hand

rink addleague CODE "Name" ["Nom"] [ABBR]
rink addteam CODE "Name" ["Nom"] ["Arena"] [--league=CODE] [--city=…]
rink addplayer TEAM FIRST LAST JERSEY POS YYYY-MM-DD [L|R] [import]

The registry validates everything it is given: names are single-line text without control characters, dates are real calendar dates, a jersey is 1 to 99, a hand is L or R. Club quotas apply when a lineup is dressed: at most three overage (20-year-old) and two import players.
