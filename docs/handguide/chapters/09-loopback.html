Static loopback addresses

Every IP address that starts a host receives one address in the loopback network 127.0.0.0/8 and keeps it for good. The workbench listens on it and records it with every line typed, so the audit trail says which computer typed what — without an IP address ever being stored in the league.

Purpose

In the reference edition a gateway serves many clients, and each client IP address receives a lease: sessions, the audit trail and the logs name a client by its loopback address, never by its IP address. The LK/Vexa edition applies the same algorithm to the one computer it runs on. The lease serves three ends: the host listens on an address that belongs to this computer alone; every ledger entry records it (the meta line's bytes 52–55), so Q AUDIT shows in its column from which computer typed each line, across sessions and restarts; and two computers that share a lease table, or a league copied between them, keep distinct addresses.

The pool

Leases come from a pool, by default 127.16.0.0/12 (--pool). A pool MUST lie inside 127.0.0.0/8, MUST be a /9 to a /24 starting on its own boundary, and MUST NOT overlap 127.0.0.0/16, which the computer itself uses (127.0.0.1, and 127.0.1.1 on many Linux systems). Addresses ending in .0 or .255 are never handed out. A pool of prefix length n therefore holds

capacity = (2^(32 − n) / 256) × 254          the default /12: 4 096 × 254 = 1 040 384 addresses

and the address at slot i is base + ⌊i / 254⌋ × 256 + (i mod 254) + 1.

Keys

A lease belongs to a key, the canonical text of the IP address:

  • surrounding white space, a port (192.0.2.44:8080, [2001:db8::2]:443) and an IPv6 zone (fe80::1%eth0) are removed;
  • an IPv4-mapped IPv6 address (::ffff:192.0.2.44) is its IPv4 address;
  • IPv6 is written as RFC 5952 prescribes (lower case, the longest run of zero groups compressed): [2001:DB8:0:0::1]:443 is 2001:db8::1;
  • optionally, an IPv6 client is keyed by its /N prefix rather than its address (the reference edition's VWS_LOOPBACK_IPV6_PREFIX; this edition uses /128).

Text that is not an IP address, or is longer than 64 characters, has no key and receives no lease.

Choosing an address

The first choice for a key is a slot computed from the key alone:

slot(key) = int( SHA-256("RINK-VT loopback 1" ‖ NUL ‖ key)[first 16 hex digits], 16 ) mod capacity

If that slot's address is held by another key, the next slots are tried in order, wrapping at the end of the pool (linear probing), and the first free address is taken. A key therefore receives the same address on any host with the same pool unless an earlier key took its slot first, and a collision moves only the newcomer. A table holds at most max_leases keys (65 536 by default); a new key beyond that, or in a full pool, is refused, never given an address another key holds.

The lease table

The table is a text file, by default loopback/leases in the data folder (--leases). Its first line is a header naming the format, the pool and the IPv6 key prefix; each later line is one lease of four fields separated by single spaces: the address, the key, the time it was made (UTC) and a seal, the first 16 hexadecimal digits of the SHA-256 of the first three fields joined by spaces.

# RINK-VT loopback leases · format 1 · pool 127.16.0.0/12 · ipv6 /128
127.20.66.113 203.0.113.5 2026-11-15T17:32:10Z aee292fc2d1a1222

A lease line is appended and synced before the address is used. A last line cut off by a stop was never handed out and is dropped when the table is next read. Any other damage refuses the table, and with it the start (exit 7): a line that does not have four fields or does not match its seal; an address outside the pool; a key that is not canonical; a second lease for one key or one address; a header of another format; or a header naming another pool or IPv6 prefix, because leases are static and a changed pool would move every one of them.

A lease table MUST NOT be edited. To begin again with a different pool, start with a new, empty table file; every computer then receives new addresses, and the from column of lines recorded before shows the old ones.

Sharing one table between computers

Several computers can share one lease table, so that each receives a different address even when their leagues are later brought together. Every allocation takes an exclusive lock file beside the table (leases.lock), re-reads the table under the lock, and appends its line before releasing the lock; a lock older than 60 s is taken to be left by a holder that died, and a host waits at most 15 s for a lock before refusing.

  1. Place the table on a folder every computer can write, for example a network share: \\server\rinkvt\leases.

  2. Start each host with --leases naming that file. Each computer's first start appends its lease; later starts find it.

  3. Give each computer its own data folder. A data folder belongs to one computer at a time, and the host refuses a folder another computer holds.

A table shared with a reference-edition gateway is not recommended: both editions read and write the same format, but the gateway holds its file for the whole of its run.

Platform behaviour

SystemBehaviour
LinuxAnswers on the whole of 127.0.0.0/8: the host listens on its lease address
WindowsAnswers on the whole of 127.0.0.0/8: the host listens on its lease address
macOSAnswers only on 127.0.0.1 unless an alias is added (sudo ifconfig lo0 alias 127.20.66.113). Without one, the host listens on 127.0.0.1 and the report says so; the lease is still made and recorded with every line

The IP address that receives the lease is the computer's primary address — the source address of its default route, determined by opening a datagram socket towards a documentation address (192.0.2.1) without sending anything — unless --address names one. A computer without a network receives the lease of the key 127.0.0.1. A laptop that moves between networks has a different primary address on each and therefore a lease for each; --address fixes the key.

Reading the table

python tools/leases.py [--data DIR | --file FILE]          the pool, its capacity and every lease
python tools/leases.py --data DIR 203.0.113.5 198.51.100.7    the lease of each address, or the address it would be offered first

The tool only reads: leases are made by a host when an address first starts it, and they never change or expire.
